# Agent Desk 产品与交互设计稿

日期：2026-10-17 · 状态：方案草案，尚未进入实现 · 暂用名：Agent Desk

## 1. 做什么

做一个接近参考截图的单窗口工作台：左侧按项目文件夹列出 Codex、Antigravity、Claude Code 会话，右侧使用选中的终端。每次创建会话都能独立选目录；切换会话不会停止其他终端。

打开应用后，可以一起启动保存的三个终端，也可以启动更多会话。会话数量不固定为三个；三种工具各开一个，只是最常用的组合。

**用户已确定：**只接这三种工具；项目和会话全部在左侧；各自选择项目文件夹；先用模拟数据体验前端交互。

**本稿建议：**Windows 桌面壳、目录与项目一一对应、会话配置自动保存、按会话选择是否随应用启动、明确的停止和移除操作。这些是设计默认值，不冒充用户已经确认的细节。

本轮只交付方案和设计文稿。现有 `agent-desk-demo.html` 保留原样；下一步先修正并演示 Mock，之后再接真实 CLI。

## 2. 能力预检与方案选择

| 候选能力 | 适用程度 | 结论 |
|---|---|---|
| 本机 codex、agy、claude | 直接适用 | 三种 CLI 均已找到；复用其登录及交互，不做模型 API 转发 |
| Electron + xterm.js + node-pty | 适合真实版本 | 桌面窗口、原生目录选择、终端渲染与进程管理各司其职 |
| 现有单文件 HTML Demo | 最适合下一步 | 直接验证项目树、切换、目录绑定、模拟运行，减少早期安装和打包成本 |
| Tabby 等通用终端；tday 等现成项目 | 可参考 | 有多终端基础，但截图式项目树和 agy 适配仍需核验或修改，暂不直接引入其整套功能 |
| Skill / CLI 脚本 | 辅助能力 | 可编排检测和构建；不能替代持续显示的桌面窗口。三种 CLI 接入稳定后再考虑沉淀安装检查流程 |
| Automation / 云端部署 | 当前不需要 | 用户要手动使用的本地工作台，不涉及定时任务或公开网站 |

已检查本机相关命令、已有技能及部分插件候选，**尚未检查完整能力目录**。本方案无需为 Demo 新装插件。比逐个窗口手工开工具更合适之处，是把目录选择、会话定位和启动配置统一保存在一个地方。

“本地工作台”指聚合壳不新增云后端；三个 AI CLI 仍可能访问各自服务，不能称为完全离线应用。

## 3. 页面结构

```text
┌ Agent Desk   [模拟演示]                     3 个终端运行中 ┐
│ 项目与会话          │ Codex · 页面开发                      │
│ [＋新建] [启动全部] │ D:\Projects\website    [停止] [···]   │
│ [搜索项目或会话]    ├───────────────────────────────────────┤
│                    │                                       │
│ ▾ website          │ 当前会话的终端输出                    │
│   ◎ Codex          │                                       │
│     页面开发   ●   │ 切到别处后，这里的任务继续运行        │
│   ✳ Claude Code    │                                       │
│     代码检查   ●   │                                       │
│ ▾ content-tools    │                                       │
│   △ Antigravity    │                                       │
│     内容整理   ●   ├───────────────────────────────────────┤
│                    │ > 输入模拟指令…                [发送] │
│ 2 个项目 · 3 会话   │ 运行中 · Codex · website              │
└────────────────────┴───────────────────────────────────────┘
```

- 左栏默认宽 280px；真实桌面窗口最小 960×640。浏览器 Demo 小于 960px 时可收起侧栏，通过“项目”按钮展开。
- 项目行显示文件夹名、展开箭头、会话数量；同名不同目录增加父级路径提示。完整路径可悬停查看。
- 会话行显示工具名、可选会话名称、状态文字和圆点；选中行使用浅蓝背景和左侧标记。后台新增输出显示小圆点，进入后消除。
- 右侧顶栏显示工具、会话名、完整目录的省略形式和控制按钮。完整路径可复制；不把 PID 放进主界面。
- 大部分面积留给终端。首版不加文件浏览器、编辑器、数据统计卡片或多栏分屏。
- Demo 底部输入框用于模拟发送；真实版本由 xterm 接收原生终端输入，不叠加一套聊天发送机制。

## 4. 项目、目录和会话

**项目就是一个目录。每次新建会话独立选目录，系统按目录自动归组。**

例如：Codex 选 `D:\Projects\website`，Claude Code 也选这个目录，两者列在 website 下；Antigravity 选 `D:\Projects\content-tools`，单独列在 content-tools 下。另开一个 Codex 选 content-tools，就放在第二组。

- Project 的 `rootPath` 创建后固定，Session 通过 `projectId` 绑定；实际启动目录从该 Project 读取。
- 不允许修改共享 `project.path` 来实现单会话换目录。
- 本版不做运行中换目录。顶栏菜单提供明确命名的“在其他目录新建会话”，旧会话继续留在原处，新会话独立创建。
- 路径不存在时，真实版本显示“目录不存在”，允许重新选目录创建会话或移除旧配置；不静默退回用户主目录。
- 同一目录归组以规范化路径为依据，不能只比较文件夹名；符号链接与大小写敏感目录的精确规则在真实接入阶段验证。

## 5. 核心操作

### 新建会话

点击“＋新建” → 选择工具（Codex / Antigravity / Claude Code） → 选择项目目录 → 可选会话名称 → “随应用启动”默认勾选 → “创建并启动”。

从项目行“＋”进入时预选该目录，仍可选择别的目录。创建成功后自动选中新会话。创建期间按钮禁用，防止重复创建。

Mock 使用预设目录和手动路径输入，按钮文案“选择模拟目录”；不读取本机文件。真实版改用系统目录选择框。HTML 上传文件夹控件无法提供可靠的本机绝对路径，不用于真实启动。

### 切换和后台运行

点击左侧会话立即切换。每个会话保存自己的输出、滚动位置和输入草稿；后台继续产生输出。新内容不得抢焦点。用户滚动查看旧内容时不强制滚到底部，提供“回到最新”。

### 启动、停止和移除

| 操作 | 结果 |
|---|---|
| 启动全部 | 启动未运行的已保存会话；不重复启动运行中的会话；单个失败不影响其他会话 |
| 启动单个会话 | 该会话启动新进程；保留本次打开应用期间的旧输出，并添加重启分隔线 |
| 中断当前任务 | 真实版转发 Ctrl+C；进程可能继续运行，不直接标成“已停止” |
| 停止终端 | 确认“停止将结束此终端中的任务”后结束进程；等待退出结果，保留当次输出 |
| 移除会话 | 确认移除配置；运行中则明确“停止并移除”，退出成功后移除。不删除项目文件 |
| 在其他目录新建会话 | 打开新建面板，预选同种工具；不改变旧会话 |

停止中禁用重复操作；无法结束时显示原因，不提前报告成功。当前会话被移除后选中相邻会话；移除最后一个会话后显示“新建第一个会话”。空项目分组随之消失。

## 6. 状态与重新打开

会话主状态：**未启动 → 启动中 → 运行中 → 停止中 → 已停止**；自然退出可直接进入已停止，启动异常进入**启动失败**。进程退出时记录退出码；非零退出可在“已停止”旁显示退出异常详情。

“运行中”只表示终端进程存活，不保证 AI 正在生成、已登录或可以接受输入。登录提示、授权询问和执行进度以 CLI 自己的终端内容为准，不从关键词猜测 Ready / Working。

- 最小化：所有会话继续运行。
- 退出应用：有启动中、运行中或停止中的会话时提示“退出将结束 N 个终端”，确认后清理相关进程。
- 再次打开：恢复项目树和会话配置，自动启动勾选“随应用启动”的会话。
- 不承诺恢复上一轮模型上下文，不重放历史指令。需要续聊时由用户使用 CLI 原生恢复能力。
- 首版不跨应用重启保存终端全文；不做托盘后台保活或守护进程。
- 手动停止不自动取消“随应用启动”；界面应能在会话菜单修改该勾选项。

Mock 刷新后恢复配置并重新运行相应模拟终端；旧输出不持久化。保存失败时显示“配置未保存”，不能伪装成功。

## 7. Demo 应展示什么

首次使用预置两个项目、三个运行中的模拟会话，分别对应三种工具，方便立即体验。之后以保存配置为准；保存了空列表也不能重新塞入示例数据。

验收顺序：

1. 点击三个会话，分别看到不同输出；后台输出回来后仍属于原会话。
2. 新建 Codex，选择另一个目录；新项目出现在左侧，其他项目路径完全不变。
3. 在同目录新建 Claude Code，加入已有项目，避免重复项目组。
4. 在 A 输入模拟任务并立刻切换到 B；A 的回复只出现在 A。
5. 停止 A，输出停止；重新启动后，旧任务的迟到回调不能写入新运行。
6. 连点“启动全部”，运行实例不重复；其余已停止会话被启动。
7. 刷新页面，项目、会话名、工具和自动启动选项恢复；没有真实 CLI 被启动。
8. 测试取消停止、移除当前会话、移除最后会话、搜索无结果、长中文路径。

Demo 不展示真实额度、真实费用或编造的模型版本；不声称任务已提交、测试已通过。所有任务输出都是标注清楚的示例。

## 8. 与 Antigravity CLI 的讨论记录

本轮实际调用本机 `agy.exe`，使用只读计划模式进行讨论。原始问答保存在 `work/antigravity-design-round*.json`，不是人工代写的 Antigravity 回复。

第一轮建议采纳：主进程管理独立 PTY、按会话 ID 隔离输出、原生目录选择、轻量配置保存、限制终端回滚行数、明确应用重启与模型会话恢复的区别。

第一轮建议调整：

- Antigravity 建议项目可作为逻辑组、会话保留任意独立 cwd；本稿收敛为真实目录分组，减少“同项目却不同目录”的歧义。
- 暂不加入全部停止、PID 展示和历史终端全文保存；保留当前用户真正要体验的流程。
- 不把“停止”等同于 Ctrl+C；不把“进程存活”等同于 AI 就绪。
- 它把部分建议列为用户已确定需求，并使用了“零云端依赖”表述；本稿已纠正。
- Windows 版本下限、CLI 专属行为和打包兼容性仍须实测，不能把评审推测当作验证结论。

第二轮：将上述收敛决策提交给 Antigravity 再评审。它认为目录绑定满足独立选择文件夹的需求，未发现阻断问题，补充了路径归一化、空分组清理、目录失效保护、停止中状态及 Windows 子进程清理要求，本稿已纳入。

两点工程判断保留：不能用简单全路径转小写覆盖 Windows 大小写敏感目录；进程清理要针对本应用创建的进程树，具体采用的 Windows 机制需实测，不无条件按进程名称批量强杀。

两轮 CLI 均返回 `SUCCESS`，完整回答已保存到本工作区；第二轮退出日志提示无法写入其个人缓存，该告警未影响本轮回答和本地讨论记录。上述讨论是方案评审，不代表真实终端兼容性已经通过。
