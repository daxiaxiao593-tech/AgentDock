## 当前行为说明

- 每条会话有自己的工作目录；不同项目目录可并行运行。多个会话若选同一目录，实际操作的是同一批文件，界面会提示共享目录风险。
- 顶部“在其他目录新建会话”会为当前工具新建一条会话，不会搬动或停止旧会话。改已有会话的目录只影响该会话，需先停止它。
- “打开 AgentDock 时启动此会话”表示打开 AgentDock 窗口时自动启动该会话的 CLI；它不表示 Windows 登录时自动启动 AgentDock。
- Codex 与 Antigravity 的基本问答已有实测。Antigravity 状态栏的 `AI: Out of credits` 与已成功的简单问答并存，不作为阻塞。Claude Code 等用户配置 API 后再测。
- 不自动安装或配置 CLI，不调整 CLI 权限，不代答确认，不扫描或重发历史提示；共享目录提醒继续保留。

## 未完成事项（按后续优先级）

### 1. 先解决用户实际遇到的目录操作问题

用户反馈“更改目录”点击无响应、也无法给每个终端单独选目录。当前界面已经把顶部操作定义为“在其他目录新建会话”；独立目录能力及目录选择器曾在 0.2.14 打包目录版、隔离假 CLI 下验证，但尚未形成 0.2.20 已安装版对这次用户反馈的复现/验收记录。

下一步应只验证这条用户路径：点击顶部按钮后是否弹出 Windows 目录选择器；选择新目录后是否新增会话并显示不同路径；原会话是否继续运行；已有会话停止后改目录是否只改该会话。先复现具体按钮和状态，再决定是否改代码，避免把“新建独立会话”和“移动现有会话”混为一谈。

### 2. 补完 0.2.20 发布验收

- 从 Desktop Known Folder 的真实快捷方式冷启动 0.2.20、重复双击，并确认仅一个窗口、无额外命令窗口；按隔离测试配置确认 CLI 自动启动行为。
- 对 0.2.20 做一次卸载保留核对。0.2.18 有卸载保留证据，但不能替代当前版本证据；不读取 CLI 历史或认证内容。
- 安装包当前未签名。带 Mark-of-the-Web 的分发包 SmartScreen/发布者提示尚未按 0.2.20 版本核验；本地构建包的结果不能代替下载包结果。

### 3. 桌面交互与显示器验收

- 标题栏物理鼠标拖动、当前版本窗口拖边缩放尚未完整核验；以真实输入操作验收，不用合成鼠标或 CSS hit-test 代替。
- 跨显示器移动需要第二台活动显示器；目前没有该验证条件，可暂缓。

### 4. UI 参考图对齐

0.2.20 已调整品牌图标、顶部信息和项目树分隔线，但应用外壳仍未达到用户要求的 100% 像素级一致。后续应以同尺寸应用内容区做逐项校准；Windows 窗口边框、系统字体/DPI 和真实 CLI 的动态终端输出并非应用可完全固定的像素目标，不应通过伪造 CLI 状态或输出来匹配静态截图。

### 5. 工作区生成物清理

上次已提交源码和文档，但递归删除命令被执行环境策略拦截，清理没有发生。当前 `node_modules`、`.cache`、旧安装包及 `dist/win-unpacked` 仍在；0.2.20 安装包需保留。`test-results` 约 504 MB，开发记录直接引用其中的截图和日志，暂时保留。lockfile、许可证、图标和源码都属于交付所需文件。

## 可以考虑的后续功能

这些是候选项，不是当前交付阻塞；建议先修复并验收目录操作，再挑一项做小版本：

1. **最近使用/收藏工作目录**：减少每次从目录选择器重新浏览的操作；新会话仍由用户明确选择路径。
2. **启动失败诊断**：清楚显示 CLI 未安装、路径无效或启动失败的原因，并提供复制诊断信息；不收集提示内容、历史或凭据。
3. **会话预设**：为常用的工具、目录和“打开 AgentDock 时启动此会话”设置提供命名预设，减少重复创建配置。

暂不建议扩展到远程访问、网关、团队协作或内置编辑器；这些会扩大安全和维护范围，当前没有必要性证据。
