## 任务 3.2：Windows PTY 安全进程树清理

- 固定 `node-pty@1.1.0`，新增 `patches/node-pty+1.1.0.patch` 和 postinstall 脚本。Windows 安装时先校验版本并应用源码补丁，再用当前 Node ABI 构建原生模块；node-gyp 头文件缓存在忽略目录 `.cache/node-gyp/`，首次构建需能下载对应版本的 Node headers。本机验证使用 Node 24.14.1、VS Build Tools 2022、Windows SDK、Spectre 库与 Python 3.14.4。
- ConPTY 补丁创建每会话独立 Job Object，设置 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`；目标进程先以挂起态创建，加入 Job 后才恢复。显式停止调用 `TerminateJobObject`，根进程退出时关闭该 Job 句柄并由系统清理剩余后代；移除上游基于异步 PID 列表的清理路径。
- 原生模块仅导出已构建 Job Object 能力标记；Windows driver 强制使用 ConPTY，并在该标记缺失时拒绝默认 kill，继续 fail-closed。不会按进程名批量终止，也不会触碰其他 PTY 或独立进程。
- `tests/node-pty-job-cleanup.integration.test.cjs` 使用本机实际编译的 node-pty / ConPTY 和假进程树验证：停止时清理 detached 后代且保留独立控制进程；根进程自然退出时也清理 detached 后代。未启动 Codex、agy 或 Claude Code。
- `tests/node-pty-conpty.integration.test.cjs` 经真实 driver / ConPTY 启动假 CLI，验证启动无自动输入、人工中文输入回显、包含中文和空格的 cwd、正常退出码及句柄释放。此用例最初暴露自然退出后 ConPTY Worker 未被 driver 释放；driver 仅在安全能力标记存在且非 stop 路径时关闭 PTY 资源，并以回归测试锁定。
- 先观察到原版进程树清理测试失败（后代存活及 `AttachConsole failed`），打补丁并重新构建后通过。先后验证补丁反向应用/重放、postinstall 原生构建、3 项真实 ConPTY 假 CLI 集成；最终完整 `npm test` 为 42 项通过，0 失败、0 跳过。MSVC 输出包含 node-pty 上游依赖的窄化转换警告，无构建错误。
