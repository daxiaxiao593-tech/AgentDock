# Agent Workbench 固定版本复用边界报告

日期：2026-10-17  
审计基线：`cvelasquez/agent-workbench` commit `856cc9713322875be02fda730f10de78ac95b1aa`，根包版本 `0.6.0`。  
审计方式：通过 GitHub Connector 按固定 commit 读取源码、包清单、Demo 脚本及 LICENSE；没有安装依赖、运行上游程序或复制上游代码。

## 裁决

**不采用 Agent Workbench 整体 fork；按现行技术方案转为复用成熟终端组件的 AgentDock 薄壳。** 上游已有可参考的 PTY、React/xterm 和 WebSocket 分层，但三 CLI 入口、终端生命周期和输出传输都与本项目约束耦合。要满足要求，必须重写权限相关启动参数、自动答复、会话恢复、三种 CLI 适配器及核心事件/流控协议；继续整体 fork 的改造面已超过可复用收益。

上游 LICENSE 为 MIT。由于本裁决不复制其实现代码，后续仅在重新评估后复用公开成熟依赖；若复制上游代码，仍须保留相应版权和许可文本。

## 行为与边界证据

| 项目要求 | 固定版本观察 | 对 AgentDock 的影响 |
|---|---|---|
| 不覆盖 CLI 权限 | Claude Code 启动参数固定传 `--permission-mode` 与 `LAUNCH_PERMISSION_MODE`；Antigravity 固定 `--mode accept-edits`。见 [Claude adapter](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/packages/server/src/agents/claude-code/index.ts#L148-L159)、[Antigravity constants](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/packages/server/src/agents/antigravity/constants.ts#L20-L27) 与 [Antigravity adapter](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/packages/server/src/agents/antigravity/index.ts#L255-L263)。 | 不能原样沿用适配器；薄壳仅传 CLI 本身必需的命令和参数，不指定权限模式。 |
| 不自动回答确认 | Claude 恢复 hook 在状态为等待对话框且输出含特定标记时，向 PTY 写入 `2` 和回车。见 [resume-dialog](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/packages/server/src/agents/claude-code/resume-dialog.ts#L107-L145)。 | 即使只针对恢复菜单，也违反“不自动回答确认框”；不复用该 hook。 |
| 不扫描原生历史 | 服务启动调用 `index.start()`；SessionIndex 随即扫描，遍历启用适配器的 `history.list()`，缓存缺失时再调用 `history.scan()`。三种原生数据根见 [Claude history](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/packages/server/src/agents/claude-code/history.ts#L1-L3)、[Codex history](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/packages/server/src/agents/codex/history.ts#L1-L4) 与 [Antigravity history](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/packages/server/src/agents/antigravity/history.ts#L251-L260)；扫描入口见 [server startup](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/packages/server/src/index.ts#L451-L462)、[session index](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/packages/server/src/session-index.ts#L657-L721) 与 [index scan](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/packages/server/src/session-index.ts#L864-L870)。 | 仅隐藏历史 UI 或关闭标签恢复不足以关闭扫描链路；独立薄壳不连接原生 history source。 |
| 不额外保存 CLI 日志 | Antigravity 默认增加每次启动的 `--log-file` 参数，源码说明日志包含 prompts；启动准备还会安装应用自己的 status-line 脚本并清理旧 CLI 日志。见 [Antigravity launch](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/packages/server/src/agents/antigravity/index.ts#L235-L263) 与 [prepare](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/packages/server/src/agents/antigravity/index.ts#L362-L372)。 | 必须移除日志、status-line 安装和清理副作用；这不是可直接复用的纯终端适配器。 |
| 不恢复模型对话 | 默认启动流程读取保存的标签并调用 `registry.restore()`；唤醒逻辑检查原生历史存在后再以 `--resume` 重开 CLI。`AGENT_WORKBENCH_NO_RESTORE=1` 只关闭标签恢复，不关闭历史索引和适配器准备。见 [server restore](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/packages/server/src/index.ts#L472-L485)、[wake/resume](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/packages/server/src/terminal-registry.ts#L417-L433)。 | 持久“会话定义”与运行实例必须拆开；保存的启动选项只创建新 run，不推断或恢复旧模型对话。 |
| 每次 run 独立隔离 | 上游有内部 `launchToken`，但输出事件仍按稳定的 `terminalId` 路由；PTY 输出回调无 runId，WebSocket `terminal.output` 也不含 runId/seq。见 [PTY output](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/packages/server/src/terminal-registry.ts#L511-L558)、[socket output](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/packages/server/src/terminal-socket.ts#L653-L657)。 | 需要在服务、协议和客户端端到端增加 runId 与序号过滤；仅给适配器加 token 不满足要求。 |
| 输出流控 | `OutputBuffer` 将重连回放限制为 256 KiB；但 PTY 数据仍直接遍历 listener，socket 对开放连接直接 `send()`，未见消费 ACK 或基于 `bufferedAmount` 的背压。见 [output buffer](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/packages/server/src/output-buffer.ts#L13-L33)、[PTY broadcast](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/packages/server/src/terminal-registry.ts#L547-L558)、[socket send](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/packages/server/src/terminal-socket.ts#L191-L199)。现有 [TerminalWriteQueue](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/packages/server/src/terminal-write-queue.ts#L4-L8) 管理的是应用写入 CLI 的输入队列，不是 CLI 输出队列。 | 输出 ACK、有界队列、慢消费者策略需重新设计；单有回放 buffer 不能证明端到端有界。 |
| Windows 进程清理 | `PtySession.dispose()` 在 Windows 调用 `pty.kill()`，没有显式 Job Object 或进程树管理。见 [pty-session](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/packages/server/src/pty-session.ts#L128-L155)。 | PTY 所属进程的退出方式仍需用可控 CLI 子进程实测；当前源码不能证明子进程树可清理。新实现必须只处理本应用创建并持有的进程。 |

## Demo 隔离检查

上游 `pnpm demo` 使用模拟 CLI，并通过隔离环境过滤 PATH、校验发现到的 CLI；但它不是无副作用的纯静态页面：Demo 会在 `os.tmpdir()/agent-workbench-demo` 下递归清理并重建 `root`、`home`、`bin`，Windows 使用 `subst W:` 挂载该目录，启动开发服务器并打开浏览器。固定临时目录意味着运行前需设置独立临时根并确认 W: 未被占用。见 [Demo runner](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/scripts/demo/run.mjs#L1-L17)、[Demo environment](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/scripts/demo/environment.mjs#L32-L75)、[fixture cleanup](https://github.com/cvelasquez/agent-workbench/blob/856cc9713322875be02fda730f10de78ac95b1aa/scripts/demo/fixtures.mjs#L926-L942)。

**本机未安装上游依赖、未运行 `pnpm demo`、未运行上游 typecheck/check，也未执行 Windows 进程树实验。** 本报告不把源码审读或上游 CI 描述成本机运行结果；上述动态验证不影响整体 fork 裁决，但在后续锁定实际组件与 Windows 进程策略时仍需做可控实验。

## 后续实现边界

- 复用 xterm.js 与 node-pty 等成熟终端组件；以 AgentDock 自身的 Workspace/SessionDefinition/Runtime 为唯一状态源。
- 三种 CLI 仅提供最小启动参数与原样环境继承；不自动注入权限参数、不自动写输入、不扫描历史、不加日志或恢复参数。
- 在自己的服务协议中实现 runId、seq、ACK/背压、后台未读计数及草稿/滚动位置持久化。
- 先用假 CLI 验证命令解析、迟到事件、重复启动、快速停止/重启和子进程清理，再接入本机 CLI；真实登录继续由 CLI 自己管理。
